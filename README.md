# business-dashboard

商品经营力首页与详情页演示项目，基于 `React + TypeScript + Vite` 构建。

## 本地运行

```bash
npm install
npm run dev
```

## 构建

```bash
npm run build
```

## GitHub Pages

- 仓库名：`business-dashboard`
- Pages 路径：`/business-dashboard/`
- 部署方式：本地构建后，手动发布 `dist` 到 `gh-pages` 分支

### 本地更新页面后如何重新发布

当你本地修改了页面、样式或数据展示逻辑后，在项目根目录执行：

```bash
npm run deploy:pages
```

建议使用流程：

```bash
npm run dev
# 本地修改并确认效果

npm run deploy:pages
```

执行完成后，最新内容会被重新发布到 GitHub Pages：

- [https://hyin9412.github.io/business-dashboard/](https://hyin9412.github.io/business-dashboard/)

### 手动发布

```bash
npm run deploy:pages
```

这条命令会：

- 先在本地执行 `npm run build`
- 再把 `dist` 内容发布到仓库的 `gh-pages` 分支
- 自动补 `404.html` 和 `.nojekyll`，方便 GitHub Pages 托管

发布完成后，可在以下地址访问：

- [https://hyin9412.github.io/business-dashboard/](https://hyin9412.github.io/business-dashboard/)

## 这个 Demo 适合讨论什么

这个项目更适合用于和产品、运营、业务同学讨论“商品经营力看板”应该呈现什么信息、按什么层级看、以及后续迭代优先级，而不是只讨论视觉细节。

### 适合讨论的大方向

- 首页到底是“经营看板入口”，还是“可直接决策的经营驾驶舱”
- 商品单选和多选时，是否应该进入不同的信息组织方式
- 首页展示的是“问题发现”还是“问题处理入口”
- 详情页应该更偏“诊断分析”，还是更偏“治理动作闭环”
- 不同角色看到的重点是否不同：产品、运营、经营分析、财务、研发

### 当前 Demo 重点展示的内容

- 首页经营看板：
  - 数据概览
  - 账期、区域等筛选方式
  - 收入、成本、利润、成本利润率等核心指标
  - 成本构成 Top10 / 成本商品 Top10 榜单
- 首页右侧经营力表现：
  - 商品单选时，按维度展示经营力状态
  - 商品多选时，按维度展示聚合达标进度
  - Top5 问题列表，帮助快速定位异常
- 首页目标进度：
  - 当前实际值
  - 达成状态
  - 目标进度条展示
- 详情页：
  - 商品多选选择器
  - 单商品诊断视图
  - 多商品聚合诊断视图
  - 问题下钻与治理入口

### 和产品/运营讨论时建议重点确认

- 经营力的一级维度是否就是现在这几类：基础配置、定价、账单
- 每个维度的“达标 / 不达标 / 风险中”判定口径是否清晰
- 首页 Top 问题应该更偏“最严重”还是“最常见”
- 多商品视图里，是否需要按商品、区域、问题类型三种方式切换
- 详情页里，哪些信息属于“看结论”，哪些信息属于“可执行动作”
- 目标进度模块要展示金额、完成率，还是目标拆解进展

### 后续可以继续补充的展示内容

- 趋势图：近 7 天 / 近 30 天经营力变化
- 问题归因：按区域、商品类型、账期聚合
- 治理闭环：责任人、处理状态、预计完成时间
- 结果对比：治理前后经营力改善效果
- 空态、异常态、加载态，方便演示完整体验
